# MVP policy and terminal UI

`src/xagent/mvp/policy.py` provides the asynchronous `DeterministicPolicy` and `ModelPolicy` adapters. The deterministic extractor accepts explicit `field=value`, `>=`, `<=`, and `~` clauses and scenario configured aliases or regex patterns. It does not infer unspecified conditions from free prose. The supplied cofounder phrase `寻找创业合伙人，每周至少15小时` yields `weekly_hours >= 15`; the venue phrase `找场地，人数30` yields `capacity >= 30`. A configured followup field produces an `ASK_OWNER` decision only when absent from the stated requirements.

Model mode uses `XAGENT_MODEL_BASE_URL`, `XAGENT_MODEL_NAME`, and `XAGENT_MODEL_API_KEY`, or explicit constructor arguments. `ModelPolicy.from_env()` is used by the CLI. It calls an HTTP chat completions compatible endpoint with JSON response mode, validates the exact output shape and value types locally, permits one repair request for malformed output, and raises `PolicyError` for refusal, HTTP failure, timeout, or a second invalid response. When the runtime provides `allowed_actions`, the prompt lists those stage-specific actions and local validation rejects any other action before state changes. It records the latest provider/model, elapsed time, and available usage in `last_metadata` and `last_usage`. The default timeout is 20 seconds. Model claims of owner approval are outside the action schema; proposal/accept decisions require `PASS` evidence, and any claimed disclosed fact must exactly match a confirmed own fact in `public_fields`. The runtime performs its own hard condition and permission checks before state changes. A live provider has not been tested because credentials and an endpoint were not supplied; local HTTP fixtures exercise the adapter.

`src/xagent/mvp/tui.py` provides `AgentApp(runtime)`. The CLI owns `runtime.start()`, HTTP service, and `runtime.stop()`; the Textual app only displays this runtime's snapshot and submits owner actions. The top shows the fixed agent identity and public profile, including confirmed remembered facts that are listed in `public_fields`. Selectors identify sessions and pending questions, the event pane updates on a short timer, and the details pane shows the selected question, proposal digest, and result. The log expands public request conditions, filter reasons, question/answer fields, proposal requirements, and policy actions using configured field labels, so an exchange is readable without parsing IDs. Untrusted event and profile text uses Rich markup disabled. A selected pending question receives bare input; otherwise bare input broadcasts a new request. The input box stays in place while new events arrive.

Typing captures the selected question at the start of a draft. If a new question arrives while a request is being typed, Enter still submits that request. The selector is updated only when session or question options change; the polling timer does not reset it every tick.

Keyboard commands:

- `/request TEXT` broadcasts an explicit new request.
- `/answer QUESTION_ID TEXT` answers the named pending question. Bare text answers the selected pending question.
- `/remember QUESTION_ID TEXT` saves a confirmed personal fact for future sessions; ordinary answers remain scoped to this session.
- `/approve [SESSION_ID]` and `/reject [SESSION_ID]` act on the displayed proposal digest and session revision. Omitting the ID uses the selected session. Ordinary text never approves.
- `/retry MESSAGE_ID` explicitly retries a blocked inbound message after a visible processing error. Error lines show the message ID and reason; no automatic model retry loop runs.
- `/sessions` lists local session states; `/help` shows controls.

Tests cover explicit extraction, scenario regexes, overlapping comparators, pass/fail/unknown choices, stage-specific allowed actions, local HTTP success/schema/refusal/error/timeout/fabricated fact behavior, selected question targeting, approval separation, remembered facts, selected-session approval, readable event details, an event arriving while a draft remains in the input, a new question not capturing an in-progress request, and explicit recovery from a blocked processing error. The terminal UI tests use Textual's [`run_test`](https://textual.textualize.io/guide/testing/) and keep runtime operations asynchronous as described in the [workers guide](https://textual.textualize.io/guide/workers/).

Cross-check: `uv run pytest -q` passed with 53 tests. It emitted one upstream `StarletteDeprecationWarning` from FastAPI's TestClient import.

Limitations: deterministic extraction deliberately handles only configured patterns and explicit field comparisons. The scenario regexes define how the demo's natural phrasing is recognized. Model mode is locally validated but not yet verified against a live provider or its exact dialect of JSON mode.
